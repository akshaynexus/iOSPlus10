# GPU kernel audit: our A730 driver against the OnePlus KGSL gen7 driver (2026-10-26)

Scope: `bsd/dev/negroni_adreno.c` and the RedwoodGPU side (`iokit/Kernel/arm/NegroniGPU.cpp`) as the
patches 0230-0237, 0281, 0285, 0286 and 0290 make them. Read-only audit. No build, no phone.

How to read this page:

- `[V]` = verified by reading the code named on the line. `[I]` = inferred, not verified.
- `ours` = `bsd/dev/negroni_adreno.c` with every `patches/xnu` patch applied (3862 lines, md5
  0a001bf99c36e7fd4f3e551db870a1cc); `GPU.cpp` = `iokit/Kernel/arm/NegroniGPU.cpp` patched (1998 lines, md5
  4cf38d1b7b6bee9c34323dcb506f5f04). Every full-patch scratch tree under `out/kernel/tree-*` has these
  files (checked in `tree-gpur`, `tree-pwr`; the scratch trees come and go). The base tree `out/kernel/xnu`
  holds the slop state before 0230 (2435 lines). Line numbers here are from the patched file.
- `KGSL` = `out/src/op-kernel/drivers/gpu/msm/`. The checkout is partial [V `ls`]: it has
  `adreno_gen7*.c/.h`, `adreno_hfi.h`, `adreno_ringbuffer.c`, `kgsl_pwrctrl.c`, `kgsl_gmu_core.c/.h`,
  `adreno-gpulist.h`, `gen7_reg.h`. It does NOT have `kgsl_pwrscale.c`, `kgsl_mmu.c`, `kgsl_iommu.c`,
  `kgsl_sharedmem.c`, `adreno_dispatch.c`, `adreno_drawctxt.c`, `kgsl_sync.c`, `adreno.c`. Rows that
  need those files are marked [I].
- DT = `out/live.dts` gpu node `qcom,kgsl-3d0@3d00000` (lines 21058-21252), gmu node (21282-21298),
  kgsl-iommu node (21254-21280).

What the phone's KGSL enables for this GPU [V `adreno-gpulist.h:2079-2110`]: `qcom,adreno-gpu-gen7-0-1`,
chipid 0x07030001, features APRIV | IOCOHERENT | CONTENT_PROTECTION | IFPC | ACD | L3_VOTE | BCL |
PREEMPTION; no LM, no DMS, no LPAC, no HW_FENCE; gpudev = `adreno_gen7_gmu_gpudev` (the non-hwsched
driver); gmem 2 MiB; `hang_detect_cycles` 0xcfffff; highest bank bit 16; firmware a730_sqe.fw,
gmu_gen70000.bin, a730_zap. DT: 12 power levels 818..220 MHz, `qcom,initial-pwrlevel` 10 (285 MHz),
`qcom,no-nap`, bus-table-ddr 12 levels, bus-table-cnoc 2 levels, ACD level per power level,
`qcom,tzone-names gpuss-0 gpuss-1` [V DT 21069-21209].

## 2. Deviations that can bite

2.1 **A lost WPTR write or a hang stops the GPU for the rest of the boot** [V]. `pm_wptr` returns false
after 200 x 10 us + one OOB GPU_SET try (ours:2642-2654) -> `negroni_gpu_submit` returns 0 (ours:3361) ->
`submitIBs` sets `gGPUStopped` (GPU.cpp:1154-1157); `gpuWait` sets it after 2000 ms without progress
(GPU.cpp:324-327); `pm_dead` after a failed wake (ours:2737). Nothing clears any of them. KGSL calls
`adreno_dispatcher_fault` in each case (adreno_gen7_ringbuffer.c:192-199, adreno_gen7_gmu.c:1519-1520)
and reboots the GMU + GPU (`gen7_gmu_reset` adreno_gen7_gmu.c:3127-3146, `gen7_boot` 2671-2700). After
our stop the Metal plugin sees device-lost, backboardd falls back to CPU copies (0254) and the phone
stays slow until a reboot.

2.2 **IFPC mode never slumbers** [V ours:2785-2808]. With IFPC on, `pm_tick` only samples; the slumber
path runs in mode slumber. KGSL slumbers from IFPC after the idle timer (gmu_idle_check
adreno_gen7_gmu.c:2870-2913 -> gen7_power_off 2795-2868): CX GDSC, GMU clocks, RSC off. Ours keeps CX,
the GMU (running firmware) and the SMMU powered forever with the screen off. For "cool" and battery, this
is the second gap.

2.3 **The governor has no real busy signal in IFPC mode** [V ours:3653-3654]. busy = "a fence is pending",
sampled every 100 ms. KGSL's governor reads the GMU power counter (busy cycles) each window
(adreno_gen7.c:1392-1445; the counter is enabled at gen7_start 521-527, which we do not write). A short
frame that completes between two ticks is invisible; a frame that straddles a tick counts as 100 ms busy.
0286's UI floor exists to paper over this. A busy counter read from the GMU (CX side, readable without
GX) would give KGSL-grade numbers.

2.4 **RB_CNTL BIT(27)** [V ours:1785]: the CP does not write the rptr shadow (KGSL leaves the bit clear,
adreno_gen7.h:186-188, and reads the rptr from memory). In IFPC mode our ring room comes from
`fence_pos` (ours:2593-2601): at most 255 outstanding fences, and no room is seen for ring space the CP
has read past the last fence. A rptr shadow (clear BIT(27), read scratch +0x80) is what KGSL does and
needs no GX read.

2.5 **Fixed bus votes, no CNOC, no ACD** [V]: the 12 DDR rows (ours:1605-1612) are the Linux msm a730
constants, not computed from this phone's cmd-db BCM data as KGSL does (adreno_gen7_rpmh.c:195-260,
458-497); the CNOC vote (DT 21078 `qcom,bus-table-cnoc <0 100>`) is absent; the bw index follows a
linear ramp (ours:3496-3505) instead of the DT `bus-freq` column. ACD is off: KGSL sends the ACD table
and feature before CORE_FW_START (adreno_gen7_hfi.c:540-561, 608) and the AOP message
(adreno_gen7_gmu.c:1795). Without ACD the GPU runs at the full voltage margin at every level [I]:
hotter per MHz.

2.6 **No HWCG (hardware clock gating)** [V ours header 43: "no clock gating"; KGSL gen7_start
adreno_gen7.c:557 writes 55 hwcg registers + RBBM_CLOCK_CNTL 0x8aa8aa82 + 3 GMU AO CGC words].
Every GPU block clocks while GX is up, idle or not. This is a direct heat cost between frames and inside
a frame.

2.7 **No CP_PROTECT, no CHICKEN_DBG, DMS not disabled** [V]: KGSL protects 48 register ranges
(adreno_gen7.c:225-258), sets CP_CHICKEN_DBG = 1 on gen7_0_1 (icache prefetch, 544-549), and sets
ME_INIT BIT(11) because gen7_0_1 has no ADRENO_DMS (adreno_gen7.c:124-126, gpulist 2085-2088). Ours
skips all three. Protect is a safety net only (our ring is APRIV). CHICKEN_DBG and DMS: unknown effect
on this silicon [I]; KGSL's choices are the tested ones.

2.8 **Cache attributes**: every GPU mapping is Normal non-cacheable (MAIR index 0 = 0x44, ours:712, 811-813),
own buffers are CPU-cached, and coherence is by `dc civac` of modified pages at submit and CPU_PREP
(GPU.cpp:368-377). KGSL on gen7_0_1 uses IOCOHERENT for cached buffers (gpulist 2085) and the SMMU's
IOMMU_CACHE attribute [I: kgsl_iommu.c absent]. Our method is correct but costs a `pmap_is_modified` walk
per page per submit (README section 7) and misses kernel-side writes after the first flush (the comment
at GPU.cpp:365-366 says buffers are flushed whole when made). Pool memory (write-combined, XNU does not
manage it) needs no maintenance, but is off by default.

2.9 **SMMU: translate for every stream, FSR never cleared, no fault IRQ** [V ours:846-861]: a fault
leaves FSR set, so every later `space_faulted` reports the same old fault and `ring_run`/`negroni_gpu_report`
treat it as current. KGSL clears FSR at boot (`kgsl_mmu_clear_fsr`, adreno_gen7_gmu.c:2627) and in the
fault handler [I].

2.10 **One ring, one sequence for every client** [V GPU.cpp:40-44]: a slow client's submission delays
backboardd's present (the 2D copy goes on the same ring behind it, README section 3). KGSL gives
backboardd-class work its own ring by priority (4 rings, preemption). For iOS this matters when a game or
Camera submits long buffers [I].

2.11 **HFI timeout 3 x 1000 ms** (ours:1356-1362) against KGSL's 100 ms (adreno_hfi.h:404): under the
power lock a stuck GMU blocks every submission and the watch for 3 s per message.

2.12 **Slumber wake misses `kgsl_mmu_flush_tlb`** (adreno_gen7_gmu.c:1892) [V]: KGSL flushes the
SMMU TLB before each GMU boot because CX may not have gone down (our case: CX never goes down). Our
`pm_wake` (ours:2704-2753) does not touch the SMMU. A stale TLB after a wake is possible [I] since the
tables may have changed while asleep (clients free buffers at any time, `negroni_gpu_unmap` does TLBIASID
only for the core context, not for the GMU's).

2.13 **GENERAL_9 (GMU log wptr) = 0 on every start** (ours:1208): KGSL writes the retained value
(adreno_gen7_gmu.c:381, 888-889). Harmless for function; the GMU log restarts [I].

2.14 **Per-client tables are CPU-switched** (ours:3207-3255) with a 2 ms idle wait and an up-to-60 s
`gpuWait` for the other client's work (GPU.cpp:1132-1147): a table switch per client change serialises
every client on an idle GPU. Default is off, so no effect today.

## 3. What remains, ordered by value for "stable, smooth, cool"

1. **GPU reset and recovery** (stable). Replace the `gGPUStopped` dead end with KGSL's recovery:
   on a lost WPTR write, a 2 s stall, a CP_HW_FAULT/INT_0 error bit or an SMMU fault: halt GBIF
   (`gen7_halt_gbif` adreno_gen7_gmu.c:2492-2511), `gen7_power_off` + `gen7_boot` (our `pm_sleep` +
   `pm_wake` already implement most of this for mode slumber, ours:2659-2753), clear FSR, reset the
   fence words, mark the fences of the lost submissions done, tell the clients (`MSM_PARAM_FAULTS`
   per-client counter, not a global flag). Add a watch-thread hang check that does not need a waiter
   (KGSL: the dispatcher timer): "a fence pending and the rptr shadow not moving for N ms".
   Prerequisite: clear RB_CNTL BIT(27) so the rptr shadow works (2.4).
2. **HWCG on** (cool). Write KGSL's 55 `gen7_0_0_hwcg_regs` + RBBM_CLOCK_CNTL + the 3 GMU AO CGC words
   at step 20 (adreno_gen7.c:265-300, adreno-gpulist.h gen7_0_0_hwcg_regs). KGSL writes them before the
   pwrup list is patched, so the list captures them.
3. **Slumber from IFPC mode** (cool, battery): after N s idle in IFPC mode run `pm_sleep` (it exists) and
   on the next submit `pm_wake`; add the GBIF halt and the TLB flush of 2.12. Then CX/GMU/SMMU are off
   with the screen off. Consider CX GDSC collapse and the GMU clocks off, as `gen7_gmu_power_off` does
   (adreno_gen7_gmu.c:2546-2555); our `gpu_stop` already collapses CX (ours:2357-2359).
4. **A real busy counter for DCVS** (smooth): enable the GMU power counter as gen7_start does
   (CX_BUSY_MASK 0xff000000, POWER_COUNTER_SELECT_0 low byte 0x20, POWER_COUNTER_ENABLE 1;
   adreno_gen7.c:521-527, 1392-1445) and read it from the watch (CX side, no GX hold). Replace the
   "pending fence" busy with busy cycles / elapsed. Keep the UI floor as a hint, not the main rule.
5. **ACD table + feature + AOP message** (cool): build H2F ACD_TBL from the DT `qcom,acd-level` values
   (adreno_gen7_gmu.c:2104-2146), send FEATURE_CTRL ACD (adreno_gen7_hfi.c:540-561), and the AOP mailbox
   `{class: gpu, res: acd, val: 1}` (adreno_gen7_gmu.c:1729-1751) before the GMU boot. The AOP mailbox
   (QMP) is a new block for us [I: nothing in the tree talks QMP]; the table and feature can be tried
   first (the GMU may accept them without the AOP message or may refuse: a log line tells).
6. **Bus votes from the DT** (smooth, cool): compute the DDR rows from cmd-db BCM aux data as
   `build_rpmh_bw_votes` (adreno_gen7_rpmh.c:121-260) and use the DT `bus-freq`/`bus-min`/`bus-max` per
   level; add the CNOC CN0 vote (bus-table-cnoc).
7. **Completion interrupt** (smooth, CPU): route RBBM INT (CP_CACHE_FLUSH_TS, bit 20) to a handler and
   wake `gpuWait` and the present path instead of 200 us polling; KGSL's `gen7_irq_poll_fence` shows the
   fence rule for IFPC (adreno_gen7.c:1153-1187). Needs the GIC path other negroni drivers use [I].
8. **CP_PROTECT, CHICKEN_DBG, ME_INIT BIT(11)** (stable): copy KGSL (2.7). Cheap, low risk.
9. **Zero page after each buffer** (stable): the GPU writes whole tiles past a surface's end
   (gpu-status.md, bergamota).
10. **SMMU fault hygiene** (stable): clear FSR after reporting; a stale fault must not fail the next
    submit's check.
11. **HFI timeout 100 ms** (stable): KGSL's value; a dead GMU then shows in 100 ms and recovery (item 1)
    can run.
12. Per-client rings/priorities and preemption: n/a until a second heavy client exists.

## 4. Risks for the queued test (IFPC on by default, image `out/ios16-perf`)

- [V] `pm_wptr` gives up after 2 ms + one OOB try and returns 0; `submitIBs` then sets `gGPUStopped`
  for good (GPU.cpp:1154-1157). An IFPC exit slower than 2 ms (the first collapse after boot, or a
  collapse during a DCVS vote) ends GPU use until reboot. KGSL tolerates up to 200 x 10 us as well
  (adreno_gen7.c:150-196) but then recovers. Mitigation for the test: `negronigpu_ifpc=0` reverts to
  slumber mode; `negronigpu_ifpc=0 negronigpu_slumber=0` to the 0281 behaviour.
- [V] The pwrup list stores CP_PROTECT_REG values of 0 and no HWCG registers: after an IFPC exit the CP
  restores what we wrote (nothing extra), so the state after a collapse equals the state before. The
  registers of step 20 that are in neither list (RB base, SQE base, RB_CNTL, APRIV, QoS, SECVID,
  HANG_INT, CMDQ, RBBM_NC_MODE) are not in KGSL's lists either (adreno_gen7.c:23-99), so KGSL relies on
  the GMU/CP to keep them: same exposure as KGSL [V], unproven on our boot path [I].
- [V] ME_INIT without BIT(11) leaves DMS on (2.7). KGSL turns it off on gen7_0_1. Unknown interaction
  with IFPC [I].
- [V] In IFPC mode the watch reads GX registers only under OOB PERFCNTR (`gx_hold`, ours:2548-2565); a
  NOT-ACKED hold is logged 4 times then silent, and the line prints `~0` for the GX words: not a failure
  of the GPU. `pm_hold_failed` is not in the WATCH line.
- [V] DCVS votes go out while GX is collapsed (`may_vote` true in IFPC mode, ours:3655). KGSL does the
  same through the GMU (the GMU applies the level at the next GX power-up) [I: not read in the GMU
  firmware].
- [V] The fence-based ring room (2.4): a burst of more than 255 submissions without a completed fence
  makes `pm_rptr_estimate` report "no room" (ours:2597-2599) and the submit path spins 2 s then returns
  0 -> `gGPUStopped`. backboardd submits ~50-120 per second with fences completing in 10-20 ms, so this
  needs a stall first [I].
- [V] `negroni_gpu_report` and the table switch take `gpu_pm_lock` (ours:3368, 3224): a report during a
  slumber wake waits for the wake (README section 16 "Risks").
- [V] The GMU may refuse FEATURE_CTRL IFPC: the code falls to slumber mode (ours:2771-2774). The GMU
  may accept and never collapse: after 10 s idle the code goes to slumber mode (ours:2794-2803). Both
  are logged. Neither is a hang.
- [I] Heat: IFPC removes GX power between frames, but HWCG is still off and ACD is off (2.5, 2.6), and in
  IFPC mode nothing ever slumbers (2.2). Expect a lower idle temperature than 0281, not KGSL's.
- [V] The USB log attaches at step 21 (notes section 17): the step-17 `FEATURE_CTRL IFPC ACCEPTED/REFUSED`
  line is only in the persistent log and in the watch's late copy at 5 s (`clock_late_report`,
  ours:3411-3453, with `negronigpu_clkdump` on).
