## 0. Two findings to fix before the queued test

1. **TLMM base is wrong in 0243** [V]. `P43:183` sets `TLMM_PHYS 0x0f000000`. The GPIO control registers of
   the SM8450 are at `0x0f100000 + 0x1000 * n`: `out/src/extra/pinctrl-sm8450.c:13,33` (`REG_SIZE 0x1000`,
   `ctl_reg = REG_SIZE * id`, no `REG_BASE`) and the mainline node is `pinctrl@f100000` (quoted in the touch
   driver that works on the phone: `external/slop/negroni-ios/xnu/patches/0093-negroni-s3908-touch-gpio-i2c.patch:1158`
   `TLMM_BASE 0x0F100000u`; the fingerprint patch uses the same, `patches/xnu/0350-negroni-fingerprint-stage-a.patch:91`).
   The downstream DT node `pinctrl@f000000` has `reg = <0xf000000 0x1000000>` (`DT:1528-1530`): the whole
   TLMM block, not the GPIO base. Effect: step 12 (`P43:607-609`) writes 4 words at `0xf079000..0xf07c000`,
   an unknown sub-block [U], and GPIO121..124 stay in function 0 (GPIO): no I2S clock or data reaches the amps.
   Fix: `TLMM_PHYS 0x0f100000`. Function 1 and the drive field are right [V]: `pinctrl-sm8450.c:1534-1537`
   (`mi2s2_sck/data0/ws/data1` are the first function), slop `TLMM_FUNC(1) = 1 << 2`, `TLMM_DRIVE_MA(8) = 3 << 6`.
2. **TLMM map breaks the io_submap rule** [V]. `P43:600-601` maps `TLMM_SIZE = 210 * 0x1000` (840 KiB) with
   `ml_io_map`. `docs/notes.md` section 20 says: anything >= 256 KiB uses `ml_io_map_unmappable` + `ml_io_unmap`.
   Budget: 840 KiB of the 8 MiB submap, permanent. Fix: map the two 16 KiB pages that hold GPIO121..124
   (`0xf179000` and `0xf17c000` are in different 16 KiB pages) with `ml_io_map`, 32 KiB in total.

## 2. Deviations that can bite

1. **No speaker protection = a real damage risk.** Android runs the NXP TFA protection in the ADSP
   (`libtfadsp_rx.so`, module 0x1700B911 in the device graph, plan [V]) with VI feedback on `MI2S-LPAIF-TX-TERTIARY`
   (`RM:461-467`) and `speaker_protection_enabled 1` (`RM:526`). The TFA9874 has no DSP (plan [V]: "non-DSP TFA").
   Without the algorithm nothing limits excursion or voice-coil temperature; only the chip's OCP/OTP/UVP stay
   (plan). Our chain today: no VOL/limiter module in the graph, the kernel sink applies mute only (`P43:1093-1094`),
   the HAL passes samples at iOS software volume. State clearly: **a full-scale signal into an amp at its
   container gain can overheat or over-drive the speaker.** Mitigation before any amp init: a kernel limiter + gain
   cap (plan: HackiOS `redwood_guard.c`), a low TDMSPKG (<= 3), amps off on silence and on panic.
2. **No ACDB calibration.** Flat output, no MBDRC/MSIIR/SAL, no per-device tuning. Sound is possible without it
   [I]; the vendor's gain structure is not reproduced, which feeds risk 1.
3. **Untranslated SMMU assumption** (`P43:911-934`). Linux translates SID 0x1801 (`q6apm-dai.c:546-549` with
   `iommus`); HackiOS programmed a stage-1 context (`redwood_sound.c:493-504`). If the SMMU faults, the symptom is
   no DONE events and possibly an LPASS hang; step 14 itself passes (the map reply is a handle, not a translation
   test) [I]. The ADSP side also has its own translation (ADSP SMMU, `qcom,smmu-sid-mask 0xf`) that TrustZone/the
   firmware set up [U].
4. **V1 data command by default** (`P43:1045`). Mainline uses V2 only; the vendor GSL too (plan [V]). If step 15
   shows writes but no DONE, run with `negroniaudio_v2=1` first (the plan says so). DONE is not matched by address
   (`P43:394-397`); a DONE for another client's buffer would count [I: no other client].
5. **No servreg locator and no PDR.** Mainline starts the PD mapper before `auth_and_reset` (`qcom_common.c:596-613`,
   `qcom_q6v5_pas.c:918`). The ADSP's `audio_pd` may wait for `GET_DOMAIN_LIST` answers [U]; then step 11 times
   out (15 s) and `negroni_audio_stop` runs. `docs/plan.md:25` wrongly names step 10 "servreg locator".
6. **No crash handling after step 8.** A fatal/wdog on the ADSP after the start is invisible; GLINK calls then time
   out (`P42:497-500` 200 ms per write, `P43:422-431` up to `budget_ms`), the writer thread of the plug-in blocks
   (not the HAL real-time thread, `P43:1066-1069`). No restart path exists; the "ADSP has run since the reset"
   check (`P40:411-418`) refuses a second start in the same boot.
7. **TLMM base** (section 0): wrong register block; also 840 KiB of io_submap.
8. **SET_CFG destination** (`P43:806` dst port 1) differs from mainline for the WR EP (`audioreach.c:1282-1283`
   dst = module iid). The APM accepts module params addressed to it [I: the vendor `AK` path does the same, plan].
9. **Device sub-graph direction/stack** differ from the mainline topology (RX vs TX, 4096 vs 8192). If GRAPH_OPEN
   returns a status, change these first [I].
10. **Charger PD side effect.** The ADSP hosts the charger PD; once the ADSP runs, charging is under the ADSP's
    control [U] (plan risk; 0274 uses it on purpose).
11. **/dev/negroni-audio is 0666** (`P43:1216`): any process can write or set the volume. Fine for tests, not final.
12. **GLINK channel table has 2 entries** (`P42:431-434`); other ADSP channels (`PMIC_RTR_ADSP_APPS`,
    `fastrpcglink-apps-dsp`, `PMIC_LOGS_ADSP_APPS`) are left unanswered (`P42:750-753`). 0274 must extend the table
    (out of scope here).
