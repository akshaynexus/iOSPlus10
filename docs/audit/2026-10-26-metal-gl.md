Scope: `userland/metal` (plugin, patches flame/0001-0012, m2v/0001-0003), `userland/turnip/mesa-patches`,
`userland/negronigl` (dylib shim + NegroniGL.bundle), `scripts/metal/*`, `scripts/gpu/*`, `docs/metal-*.md`,

flame/0001-0012 (2551 lines; the unpatched `external/ios-flame/phone/metal2/NativeBridgeMetalFrontend.mm` has 1758).

`external/metal2vulkan` 720ef1ce (working copy `out/metal/src/metal2vulkan`), Mesa 25.0.7 in `out/gpu/mesa-25.0.7`

## 0. Summary

- The Metal stack is complete for CoreAnimation's needs and ran on the phone: backboardd 150 s and SpringBoard 160 s
  on the GPU without a crash (notes.md:672-680) [V]. It is not stable for every process: three crash classes are open
  (section 4).
- Of the 12 frontend patches, 0001-0008 and 0012 are fixes a hardware run forced; 0009-0011 add API surface (MSL
  source, argument buffers, indirect work) for Safari. 0011 and 0012 are not exercised on the phone yet
  (notes.md:735, 776-777).
- The GL path has two routes (backboardd shim and NegroniGL.bundle for apps). `ngl_test` passed on the phone
  (notes.md:1096-1101) [V]. backboardd on GL crashed twice in CoreAnimation before our shim was reached
  (notes.md:1105-1114) [V]; the kernel fix 0257 and the userland guard are built, not run (notes.md:1133-1145).
- Documentation drift found in 7 places (section 5).

### 2.3 Kernel dependency: IOSurface CPU lock versus `gpuFence`

- `glFlush` is enough for the display chain: freedreno never defers a submit that lists a shared bo, msm has no submit
  thread, the kernel marks the listed surfaces with the fence (0230) and 0254 waits on it at SwapEnd
  (docs/gpu-userland.md:212-221; docs/gpu-abi.md:281-305) [V code].
- Not covered: a CPU reader of a GPU-written surface (`IOSurfaceLock` + read: CA CPU fallback, screenshots, a
  CPU-composited backboardd sampling an app's surface). The kernel lock does not wait for `gpuFence` and does not drop
  the CPU lines (docs/gpu-userland.md:222-223; notes.md:1175-1177) [V]. Until then: `phone-gl.sh finish on`
  (`glFinish` on every flush, `view.c:104-105`) is the safe setting [V code].
- The same gap applies to Metal in processes other than backboardd: the frontend's `flushSurfaces` (dc civac by user
  pointer) and the seed bump cover the plugin's own completions (patched frontend:362, 1244), not a reader in another
  process [I].
- Proposed and not done: kernel property `RedwoodWaitsForGPU` (the ios-spes/HackiOS contract, `external/hackios-xnu-userland/userland/src/eagl.c:4036-4045`,
  `external/ios-spes/NOTES.md:1386-1388`) so the library chooses finish/flush itself (notes.md:1177-1179) [V].

### 3.5 negronigl versus the references

- Shim: 14 selectors replaced (`eagl.c:806-821`) against HackiOS/spes's 8 (docs/gpu-userland.md:124, notes.md:1064);
  the 6 extra are the drawable/present forms, `dealloc` and the 9-argument `texImageIOSurface`. Mesa is linked into the
  dylib (no libOSMesa), the IOSurface is bound directly as the GL resource (no mirror copy, docs/gpu-userland.md:126) [V].
- Fence contract: spes uses `glFinish` unless `RedwoodWaitsForGPU`; ours uses `glFlush` by default and trusts kernel
  0254 (`view.c:20-27`). The default is right only on kernels with 0254; there is no runtime check of the kernel
  (the `RedwoodWaitsForGPU` property is proposed, not implemented, notes.md:1177-1179) [V]. Risk: an older kernel
  image with the new dylib shows frames before the GPU is done.
- `FD_MESA_DEBUG=sysmem` and `IR3_SHADER_DEBUG=nofp16` set by default (`negronigl.c:21-25`): sailfish lessons; sysmem
  gives up GMEM tiling on the A730 [I: a performance cost, not measured].
